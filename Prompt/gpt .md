Thought for 20s

ได้ครับ นี่คือ prompt พร้อมวางใน Gemini Canvas ได้เลย ผมเขียนให้เป็นแนวที่เน้น ใช้งานหน้างานเร็ว, mobile-first, เป็น PWA, และรองรับหลายผลไม้ ครับ

Prompt หลัก
ช่วยออกแบบ UX/UI สำหรับระบบ PWA บันทึกน้ำหนักผลไม้ สำหรับใช้งานหน้างานจริง โดยเน้นความเร็วในการกรอกข้อมูล, ลดความผิดพลาด, ใช้งานง่ายบนมือถือ, และดู modern / clean / professional

บริบทธุรกิจ:
- ใช้ในหน้างานคัดแยก / ชั่งน้ำหนักผลไม้
- ผู้ใช้งานต้องกรอกข้อมูลเร็วมาก
- ไม่ต้องการ flow ที่ซับซ้อน
- ต้องเห็นยอดรวมแบบ realtime
- ระบบต้องรองรับหลายผลไม้ ไม่ใช่แค่มะละกอ

เป้าหมายหลักของ UX:
1. กรอกข้อมูลให้เร็วที่สุด
2. ลดการกดหลายครั้งเกินจำเป็น
3. ลดโอกาสกรอกผิด
4. เห็นผลรวมแต่ละประเภทและยอดรวมสุทธิทันที
5. รองรับการใช้งานบนมือถือเป็นหลัก (mobile-first PWA)

โครงสร้างระบบ:
1. หน้าบันทึกข้อมูล
2. หน้าประวัติ / ค้นหาข้อมูลย้อนหลัง
3. หน้า Master Data ผลไม้
4. หน้า Master Data ประเภท
5. หน้า Mapping ผลไม้กับประเภท
6. Dashboard สรุปภาพรวมแบบเรียบง่าย

Business Logic:
- ผู้ใช้ต้องกำหนด “วันที่”, “รอบที่”, และ “ผลไม้” ก่อนเริ่มรอบ
- เมื่อเลือกผลไม้แล้ว ระบบต้องแสดงเฉพาะ “ประเภท” ที่เกี่ยวข้องกับผลไม้นั้น
- ตัวอย่างประเภทของมะละกอ: ยาว, แหลม, กลม, ตั้งฉ่าย, ลาย
- ผู้ใช้เลือกประเภท 1 ครั้ง แล้วสามารถกรอกน้ำหนักทีละค่าได้ต่อเนื่อง
- 1 ค่า = 1 รายการ เช่น 52, 45, 53
- ทุกครั้งที่เพิ่มข้อมูล ระบบต้อง:
  - เพิ่มรายการล่าสุดเข้า list
  - รวมยอดของประเภทนั้นทันที
  - รวมยอดสุทธิของรอบทันที
  - ล้างช่อง input และ focus กลับที่ช่องกรอกตัวเลขอัตโนมัติ
- ต้องมีปุ่มลบรายการล่าสุด และลบรายบรรทัดได้
- ต้องมีการป้องกัน error เช่น กรอกจำนวนไม่เป็นตัวเลข, ยังไม่เลือกประเภท, ยังไม่เริ่มรอบ

รายละเอียดหน้าจอที่ต้องการ:

A) หน้าบันทึกข้อมูล (หน้าหลักที่สำคัญที่สุด)
ออกแบบให้เป็นหน้าที่เร็วมากสำหรับการใช้งานจริง โดยมีองค์ประกอบ:
- วันที่
- รอบที่ (ตัวเลข)
- ผลไม้ (dropdown หรือ selector)
- ปุ่ม “เริ่มรอบ”
- ปุ่มประเภทแบบใหญ่ กดง่าย เห็นชัด เช่น chip / segmented buttons / cards
- ช่องกรอก “จำนวน / น้ำหนัก” แบบตัวเลข
- ปุ่ม “เพิ่ม”
- รองรับกด Enter ได้
- แสดงประเภทที่ active อยู่ชัดเจน
- แสดงรายการล่าสุดที่เพิ่มเข้ามา
- แสดง subtotal ของแต่ละประเภท
- แสดง grand total / ยอดสุทธิของรอบ
- มีปุ่ม “ลบล่าสุด”
- มี empty state, loading state, error state
- ออกแบบให้ใช้งานมือเดียวได้บนมือถือ

B) หน้าประวัติ / ค้นหา
- ค้นหาตามวันที่
- ค้นหาตามรอบ
- ค้นหาตามผลไม้
- แสดงผลรวมของรอบ
- กดเข้าไปดูรายละเอียดรายการทั้งหมดในรอบได้
- มีปุ่มแก้ไข / ลบรายการบางตัวได้
- มี summary card ที่อ่านง่าย

C) หน้า Master Data ผลไม้
- เพิ่ม / แก้ไข / ปิดใช้งานผลไม้
- ตัวอย่าง: มะละกอ, มะม่วง, กล้วย, ส้ม
- มี list view + form modal หรือ side panel

D) หน้า Master Data ประเภท
- เพิ่ม / แก้ไข / ปิดใช้งานประเภท
- รองรับประเภทที่ใช้กับผลไม้หลายชนิดได้

E) หน้า Mapping ผลไม้กับประเภท
- เลือกผลไม้ 1 ชนิด
- เลือกประเภทที่ต้องการให้ใช้ได้
- จัดลำดับการแสดงผลประเภทได้
- เปิด/ปิดการใช้งานได้

F) Dashboard
- สรุปยอดตามวัน
- สรุปยอดตามผลไม้
- สรุปยอดตามประเภท
- ใช้การ์ดและกราฟแบบเรียบง่าย
- ไม่รก แต่ดูเป็นมืออาชีพ
